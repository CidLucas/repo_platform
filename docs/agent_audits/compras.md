## Agent Logical Map

**Role**: Full procurement lifecycle manager for the company. The agent owns the supplier catalogue and the entire buying flow from identifying a need through to creating a confirmed purchase order.

**Typical flow**:
1. User identifies a procurement need (item, quantity, urgency)
2. Agent calls `list_suppliers` to surface relevant suppliers for selection
3. Agent checks `inventory_digest` for current stock levels — may deprioritize if stock is acceptable
4. Agent drafts RFQ content and confirms recipient list with user
5. Agent dispatches via `send_rfq_via_channel` (WhatsApp) — only after rfq_requests record exists
6. Supplier replies arrive → `parse_incoming_reply` with `context_type='rfq'` structures responses
7. Agent builds comparison table (supplier / unit price / lead time / payment terms)
8. User selects preferred supplier — explicit confirmation required
9. Agent creates PO via `create_purchase_order` with confirmed fields only

**Handoffs**:
- → **data-entry**: after PO approval, if the user needs to register the transaction in the financial ledger
- → **financeiro**: if the user asks for financial analysis beyond procurement scope (budget impact, cash flow)
- → **frontdesk**: if the request is not procurement-related
- ← **frontdesk**: routes procurement/supplier/RFQ queries here
- ← **compras_monitor routine**: triggers `inventory_digest` skill on schedule for low-stock/PO status digest

**Decision constraints**: Strong HITL gates on both PO creation and RFQ dispatch. The agent never commits financial obligations without explicit user approval — aligns with the platform's human-in-the-loop principle.
