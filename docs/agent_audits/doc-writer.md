## Agent Logical Map
The doc-writer follows a structured creation loop:

1. **Intake** — Receives a request to write, draft, or edit a document. Determines type, audience, and formality.
2. **Knowledge retrieval** — Always calls `executar_rag_cliente` first to avoid duplication and find existing tone/terminology.
3. **Outline confirmation** — Presents proposed structure for human approval before writing (HITL checkpoint #1).
4. **Writing** — Produces full markdown document with proper hierarchy.
5. **Storage decision** — Asks user whether to save to Google Docs (external/formal) or Notion (internal/wiki) or keep in chat.
6. **Save** — Calls `google_docs_create`/`notion_create_page` or `google_docs_update`/`notion_update_page` for edits.
7. **Approval gate** — For financial, legal, or client-facing docs: calls `submit_document_for_approval` (HITL checkpoint #2).

**Handoffs:**
- Receives context from `context-gatherer` (knowledge base is pre-populated by context-gatherer)
- Uses `data_access` skill (read-only RAG) as prerequisite before every document
- May write to KB via `knowledge_base_write` skill after producing approved documents
- `frontdesk` routes requests here when intent matches: write, draft, create document, SOP, proposal, brief, report
