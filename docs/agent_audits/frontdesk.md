## Agent Logical Map

**Role**: Entry-point dispatcher for all user interactions. The frontdesk is the only agent users interact with directly in the standard flow.

**Decision flow (5 ordered steps):**
1. **Specialist routing** — if intent matches any domain specialist (fiscal, data-entry, crm, financeiro, compras, platform, agenda, data-analyst, doc-writer, strategy), delegate immediately via `route_to_specialist`. No pre-processing.
2. **Direct SQL** — factual queries that don't belong to any specialist (e.g. "how many orders today?") are answered inline via `execute_sql`.
3. **RAG lookup** — policy/product/FAQ questions answered via `executar_rag_cliente`.
4. **Direct reply** — greetings, system questions, confirmations.
5. **Clarification** — ambiguous requests get a single focused question.

**Handoffs to**: all 10 domain specialists. The frontdesk never receives handoffs (it's always the entry point).

**Handoffs from**: none in standard flow. Platform/context-gatherer agents may operate independently outside the frontdesk flow (see comment in templates.py L2193).

**Key design decisions:**
- Golden rule: "when in doubt, always delegate" — prevents the frontdesk from overstepping into specialist domains
- Write operations are strictly forbidden via SQL — all writes go through specialists
- Output is constrained to 2-3 sentence summaries since data appears in UI tables
- SQL rules are explicit and conservative (stop on error, no retry) — appropriate for small LLM
