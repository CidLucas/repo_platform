## Agent Logical Map

**Role**: The Platform Agent is the "builder" in the Blu system — the only agent that creates and modifies platform entities (routines, goals). It does not analyze; it configures.

**Typical flow**:
1. Frontdesk receives intent → routes to platform agent when keywords match "criar rotina", "meta", "automatizar", "configurar"
2. Platform agent calls `listar_*` to check for duplicates and show existing state
3. If missing fields: asks 1-2 targeted questions (trigger, recipient, KPI target)
4. Presents a 2-3 line plain-language plan → explicit confirmation gate
5. Executes creation tool → confirms with when the action takes effect
6. If custom routine needs approval: calls `enviar_rotina_para_aprovacao` → informs user of pending state

**Handoffs**:
- **Receives from**: frontdesk (routing decision)
- **Redirects to**: financeiro (financial analysis), crm (customer data), compras (procurement data), data-analyst (trends/analytics)
- **Does NOT call other agents directly** — just informs user to ask a different specialist

**Guard rails**: Strict confirmation gate (cannot be bypassed), duplicate detection before creation, max 6 turns, no data analysis scope.

**Small-LLM fitness**: ✅ Excellent — responsibilities are enumerated (1, 2, 3), tool rules are explicit with required fields listed, output format is prescriptive. No vague "use judgment" directives.
