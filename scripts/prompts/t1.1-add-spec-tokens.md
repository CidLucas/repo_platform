# T1.1 — Adicionar tokens faltantes do spec ao global.css

## Contexto

O `blu-design-system.html` (em `apps/blu_v3/public/blu-design-system.html`) é a fonte da verdade dos tokens CSS. Ele define em seu `<style>` inline (linhas 11-90) os tokens para `:root[data-theme="dark"]` e `:root[data-theme="light"]`.

O `apps/blu_v3/src/styles/global.css` NÃO tem vários tokens que o spec define. Precisamos adicioná-los.

**Importante:** O global.css usa `:root` (não `:root[data-theme="dark"]`) para o tema escuro default, e `body.light` para o tema claro. Respeitar essa estrutura.

## Tokens a adicionar

### No bloco `:root` (tema escuro default)

Adicionar APÓS `--chart-8: #8B5CF6;` (linha ~44) e ANTES de `/* shadows */`:

```css
/* design-system spec tokens — acento extendido */
--ac-hi:    #a07ae8;
--ac-grad:  linear-gradient(135deg,#7E5CC8,#3A80D4);

/* design-system spec tokens — paleta de agentes/salas (seção 1.3) */
--pink:     #f472b6;
--teal:     #2dd4bf;
--yellow:   #fbbf24;
--orange:   #fb923c;
--violet:   #a78bfa;
```

### No bloco `body.light`

Adicionar APÓS `--muted2:` e ANTES do fechamento `}`:

```css
--ac-hi:    #7C3AED;
--ac-grad:  linear-gradient(135deg,#6D28D9,#3A80D4);
```

**Observação:** --pink, --teal, --yellow, --orange, --violet mantêm o mesmo valor nos dois temas (são cores de agente, não semânticas).

### Verificação

1. `grep -c "ac-hi\|ac-grad\|pink\|--teal\|yellow\|orange\|violet" global.css` — todos devem aparecer
2. `npx tsc --noEmit` — sem erros novos (mudança só em CSS)
3. Os valores EXATOS do spec devem ser preservados (#a78bfa, não #8b5cf6 para --violet)

## Arquivos para modificar

- `apps/blu_v3/src/styles/global.css` — APENAS adicionar tokens

## Não fazer

- ❌ Não modificar o spec HTML (ele é a referência)
- ❌ Não modificar .tsx
- ❌ Não inventar tokens que não estão no spec (ex: --brand-orange, --slate-400, --google-blue, etc.)
- ❌ Não remover tokens existentes
- ❌ Não mudar valores hex — usar EXATAMENTE o que o spec define
