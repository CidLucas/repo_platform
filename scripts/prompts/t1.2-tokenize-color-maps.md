# T1.2 — Tokenizar mapas de cor por categoria

## Contexto

Dois mapas de cor hardcoded nos componentes usam hex literais em vez de `var(--...)`. Agora que os tokens foram adicionados em global.css (T1.1), podemos referenciá-los.

## Arquivos e mudanças

### 1. `apps/blu_v3/src/pages/app/AgendaRoom.tsx`

**Linha 42-45** — DOT_COLORS:
```ts
const DOT_COLORS: Record<string, string> = {
  approval: '#fb923c',    // → 'var(--orange)'
  calendar: '#818cf8',    // → 'var(--blue3)'
}
```

**Linha 195** — fallback:
```ts
background: DOT_COLORS[ev.agenda_source] ?? '#818cf8'
```
→
```ts
background: DOT_COLORS[ev.agenda_source] ?? 'var(--blue3)'
```

**Linha 294** — fallback no inline style:
```ts
background: DOT_COLORS[ev.agenda_source] ?? '#818cf8'
```
→
```ts
background: DOT_COLORS[ev.agenda_source] ?? 'var(--blue3)'
```

### 2. `apps/blu_v3/src/components/agenda/MonthlyGantt.tsx`

**Linha 58-66** — ROUTINE_COLORS:
```ts
const ROUTINE_COLORS: Record<string, string> = {
  Financeiro:  '#8b5cf6',     // → 'var(--violet)'
  Compras:     '#8b5cf6',     // → 'var(--violet)'
  Clientes:    '#8b5cf6',     // → 'var(--violet)'
  Agenda:      '#8b5cf6',     // → 'var(--violet)'
  Documentos:  '#8b5cf6',     // → 'var(--violet)'
  'Estratégia':'#8b5cf6',     // → 'var(--violet)'
  Geral:       '#8b5cf6',     // → 'var(--violet)'
}
```

**Linha 68-74** — SOURCE_COLORS:
```ts
const SOURCE_COLORS: Record<string, string> = {
  monday: '#3b82f6',     // → 'var(--blue2)'
  notion: '#3b82f6',     // → 'var(--blue2)'
  asana:  '#F06A6A',     // → 'var(--urg)' (ou manter como slack-red se for integração)
  linear: '#5E6AD2',     // → 'var(--indigo-500)' (bem próximo)
  google: '#4285F4',     // → 'var(--google-blue)'
}
```

**Linha 781** — fallback:
```ts
const srcColor = SOURCE_COLORS[project.source] ?? '#6b7280'
```
→
```ts
const srcColor = SOURCE_COLORS[project.source] ?? 'var(--slate-400)'
```

## Observações importantes

- `#3b82f6` → já existe como `--blue2`
- `#818cf8` → já existe como `--blue3`
- `#8b5cf6` → agora `--violet`
- `#4285F4` → agora `--google-blue`
- `#F06A6A` → mapear para `--urg` (#EF4444) — é próximo o suficiente para propósito de categorização
- `#5E6AD2` → mapear para `--indigo-500` (#6366F1) — próximo
- `#6b7280` → mapear para `--slate-400` (#94a3b8) — ou usar `--mu` que é o cinza semântico

## Verificação

1. `npx tsc --noEmit` — não deve introduzir erros novos
2. Os valores usam `var(--...)` string, não precisam de CSS
3. O fallback `??` continua funcionando
